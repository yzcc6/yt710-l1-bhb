# 第一部分 · 实验设计

## 1. 一点必要回顾：为什么 BHB 能左右间接分支

Spectre v2 的落点是**间接分支**（`br x0`）——目标在寄存器里，CPU 必须**猜**。猜的时候用两样东西做索引：

```
索引 = (间接分支自己的地址, 最近 N 条分支的历史哈希)
```

这个"最近 N 条分支的历史"，就是 **BHB（Branch History Buffer）**。每执行一条分支，硬件自动把它的信息揉进这个滚动哈希；**没有任何指令能直接写它**。

> **一句话：你不能改 BHB，你只能"演给它看"——执行一串分支，让它自己记下来。**

攻击的本质是**哈希碰撞**：两段不同代码，只要到达同一间接分支前走过的分支序列产生**相同的 BHB 哈希**，就落到预测表同一项——一段代码的训练会影响另一段。这就是 **BHI（Branch History Injection）**。

## 2. 为什么必须"配对"

### 2.1 上游 harness 的三个缺陷

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | **一次运行只在开头抽 1 条训练链**，整轮复用 | 整个 run 只回答"这一条链行不行"，运行间方差极大（同一配置见过 0 / 3 / 42 次） |
| 2 | 没有零假设分布 | 看到 `hits=51`，不知道"纯噪声能到多少" |
| 3 | 没有配对对照 | 只能比较不同时间的两次运行 |

### 2.2 本实验的解法

```
对每条随机训练链（hit_num 条）：
    生成训练链（HISTORY_SIZE 条随机地址），jit
    对每条随机触发链（rounds 条）：
        生成触发链，jit
        随机决定 CTRL/MAIN 先后（记录在 order 列）
        CTRL：训练到安全目标 ftable[0] → 冲刷 → 触发 → 计时  × iters
        MAIN：训练到攻击目标 ftable[1] → 冲刷 → 触发 → 计时  × iters
```

**关键：同一条触发链、同一时刻、同一个核，只改"训练到哪个目标"。**

> **一句话：同一把锁，用两把钥匙各试一次，现场对比——而不是今天试 A、明天试 B。**

## 3. 一次测量的四个步骤

```c
for (int t = 0; t < train_n; t++) hit_ptr(tgt, fr_buf);   // ① 训练
clflush(&ftable[0]);                                      // ② 冲刷
clflush(&ftable[1]);
clflush(fr_buf);
ret_ptr(&ftable[0], fr_buf);                              // ③ 触发
uint64_t dt = load_time(fr_buf);                          // ④ 计时
```

| 步骤 | 作用 | 为什么必须这样 |
|---|---|---|
| ① 训练 | 把攻击者的历史写进 BHB，并让预测器学到"这段历史 → 攻击目标" | **唯一能影响 BHB 的手段** |
| ② 冲刷 | 保证后面测到的"快"是**这次**被摸，不是上次残留 | `dc civac`（arm64 的 clflush） |
| ③ 触发 | 走一条**尾部地址相同**的链，看预测器会不会认错 | 尾部相同 = in-place |
| ④ 计时 | 命中 → 投机执行真的发生了 | `cntvct_el0`，1 tick = 20 ns |

## 4. 统计单位：轮，不是次

| 概念 | 定义 | 本实验规模 |
|---|---|---|
| **1 次测量** | 上面四步走一遍 | 4000 万次（主实验） |
| **1 轮** | 一条触发链 × `iters` 次测量 → `hits`（0~100） | 40 万轮 |
| **样本** | 200 条训练链 × 1000 轮 | — |

> 一轮内的 100 次共用同一条链，**不独立**。把 4000 万次当样本算统计，会构成**伪重复（pseudoreplication）**。

### 改动 1：`helper.h` 计时源

```diff
 #elif ARCH == ARMV8
     uint64_t result;
-    fence();
-    asm volatile("mrs %0, pmccntr_el0" : "=r" (result));
-    fence();
+    __asm__ __volatile__("isb\n\tmrs %0, cntvct_el0" : "=r" (result));
     return result;
```

**为什么连 `fence()` 一起删**：`fence()` = `dsb ish`，要几十 ns；`load_time()` 每次调用两次 `rdtscp()`，屏障开销会被算进"读一次要多久"，把两个峰整体抬高。

## 8. `bhb_final.c` 逐段解析

### 8.1 JIT：把地址串变成分支链

```c
static void jit(uint8_t *mem, const uint64_t *history, int hist)
{
    for (int i = 0; i < hist - 1; i++) {
        uint32_t offset = (uint32_t)((history[i+1] >> 2) - (history[i] >> 2));
        uint32_t opcode = B_OPCODE | (offset & B_OFF_MASK_OPC);
        memcpy(&mem[history[i]], &opcode, 4);                     // 写 B 指令
        __clear_cache(&mem[history[i]], &mem[history[i] + 4]);
    }
    memcpy(&mem[history[hist-1]], (void *)&ind_gadget, 8);        // 末端放间接 gadget
    __clear_cache(&mem[history[hist-1]], &mem[history[hist-1] + 8]);
}
```

- 每个 `history[i]` 处写一条 `B`（无条件跳转），跳到 `history[i+1]`；
- 链尾放 8 字节的 `ind_gadget`——`ldr x0,[x0]; br x0`，**这就是被预测的间接分支**；
- 地址随机：`(rand() & 0x1ffffff) << 2`，覆盖 128 MB 的 JIT 区。

### 8.2 两条链的构造

```c
gen_history(hit_history, hist, NULL, 0);            // 训练链：全随机
jit(g_mem, hit_history, hist);
t_chain hit_ptr = (t_chain)&g_mem[hit_history[0]];

gen_history(ret_history, hist, hit_history, hist);  // 触发链：避开训练链地址
for (int t = 0; t < tail_match; t++)                // in-place：尾部复用
    ret_history[hist-1-t] = hit_history[hist-1-t];
jit(g_mem, ret_history, hist);
t_chain ret_ptr = (t_chain)&g_mem[ret_history[0]];
```

**`--tail-match`** 控制复用尾部几条：`1` = 上游原地语义，`0` = 异地，可到 64（用于证伪实验）。

### 8.3 配对循环（核心）

```c
int main_first = rand() & 1;                          // 掷硬币定顺序
for (int phase = 0; phase < 2; phase++) {
    int is_main = main_first ? (phase == 0) : (phase == 1);
    t_target *tgt = is_main ? &ftable[1] : &ftable[0];  // 只改这一个下标
    for (int k = 0; k < iters; k++) {
        for (int t = 0; t < train_n; t++) hit_ptr(tgt, fr_buf);
        clflush(&ftable[0]); clflush(&ftable[1]); clflush(fr_buf);
        ret_ptr(&ftable[0], fr_buf);                    // 两种模式触发完全相同
        if (load_time(fr_buf) < thr) hits++;
    }
}
```

**唯一变量就是 `tgt`**：`&ftable[1]`（攻击目标）或 `&ftable[0]`（安全目标）。

### 8.4 三个闸门

| 闸门 | 做什么 | 期望 | 失败返回 |
|---|---|---|---|
| `[ruler]` | cached vs flushed 是否分离 | flushed > cached + 2 | 2 |
| `[POS]` | 架构**真跳** `hit_gadget`，`fr_buf` 必被摸 | ≥95% | 3（测量链路失效） |
| `[SELF]` | 训练链与触发链**完全相同**，看能否抓到瞬态 | ≥5%（固定 8 次训练） | 4（抓不到瞬态） |

> **设计要点**：闸门用**固定的 8 次训练**，与实验的 `--train-n` 解耦——否则 `--train-n 1` 时 SELF 不稳（实测 6%~22%）会误伤正常实验。

## 9. 主结果

**配置**：`--history 256 --train-n 1 --hit-num 200 --rounds 1000 --iters 100 --thr 4 --seed 42`

```text
[result] MAIN n=200000 mean=16.6056 | CTRL n=200000 mean=0.0648 | ratio=256.3x
```

| 指标 | MAIN | CTRL |
|---|---|---|
| 轮数 | 200,000 | 200,000 |
| **均值（hits/轮）** | **16.6056** | **0.0648** |
| **均值（命中率）** | **16.61%** | **0.065%** |
| 单轮最大 | 58 | 4 |
| `≥10` 轮数 | 154,000（**77.0%**） | **0** |

**三条判读**：

1. **倍数 256.3×** —— 差异不是测量噪声；
2. **CTRL 的 `≥10` 为 0** —— 20 万轮里对照组从未强碰撞；
3. **77.0% 的轮次 `≥10`** —— 不是"偶尔撞一次"，是"大多数时候都能撞"。

## 10. 三条独立对照

### 对照①：CTRL vs MAIN（训练目标）

见 §9：**16.61% vs 0.065%，256 倍**；CTRL 的 `≥10` 在 20 万轮中为 **0**。

### 对照②：异地 vs 原地（最后一条地址是否复用）

| H | 测量次数 | MAIN 均值% | MAIN 最大 | CTRL 均值% |
|---|---|---|---|---|
| **64** | 4,000,000 | **0.00** | 0 | 0.000 |
| **256** | 4,000,000 | **0.00** | 0 | 0.000 |

> **800 万次异地测量、零命中**（此前独立测量累计更达 4600 万次）——说明效应依赖"最后一条地址复用"，**不是链长本身**。

### 对照③：尾部匹配条数（H=256）

| tail_match | MAIN 均值% | MAIN 最大 | CTRL 均值% |
|---|---|---|---|
| **1**（=上游原地） | **20.87** | 62 | 0.064 |
| 8 | 19.21 | 57 | 0.340 |
| 16 | 16.97 | 55 | 0.262 |
| 32 | 18.17 | 55 | 0.173 |
| 64 | 18.34 | 64 | 0.104 |

**两条结论**：

1. **MAIN 无单调趋势**（20.87 → 19.21 → 16.97 → 18.17 → 18.34）→ **"匹配的历史足迹越多越容易撞"不成立**；
2. **CTRL 随 tail_match 上升**（0.064 → 0.340）→ 共享的地址越多，对照组也越容易被"顺带"命中，**但始终比 MAIN 低两个数量级**。

1. **形状**：上升（64→256）→ 平台（256~288）→ 断崖（384 归零）。**不是单调，"越长越好"是错的。**

3. **两端的 `GATE_FAIL` 本身是结论**：H=32 与 H=512 时 `SELF` 自撞都跌破 5%——**极短链填不满 BHB，极长链又把它挤出有效窗口**，两种情况下 harness 连"自己撞自己"都做不到。

## 12. 参数标定 B：重复性

| H | run1 | run2 | 均值 | 差值 |
|---|---|---|---|---|
| **256** | 17.63 | 21.33 | **19.48** | **3.70** |
| **288** | 17.94 | 17.48 | **17.71** | **0.46** |

**这是本实验最重要的细节之一**：

| | 256 | 288 |
|---|---|---|
| 均值 | **更高**（19.48） | 略低（17.71） |
| 稳定性 | ❌ 差 3.70 | ✅ **差 0.46（稳 8 倍）** |

**基线参数该选哪个，取决于你要"最高"还是"最稳"。**

# 第四部分 · 结论与分析

## 16. 最终判定

| 项 | 结论 |
|---|---|
| **原语存在性** | ✅ **success**：MAIN **16.61%** vs CTRL **0.065%**（**256 倍**）；CTRL 的 `≥10` 在 20 万轮中为 **0** |
| **失败模式** | `failure_mode = null`（未触发 E001~E005） |
| **可复现性** | 同一命令 + 同一 `--seed` → 逐行一致 |

## 17. 三个参数的最终取值

| 参数 | 值 | 依据（全部来自本文数据） |
|---|---|---|
| **`HISTORY_SIZE`** | **256** | 轻训练峰 21.49%（§11）、重训练 31.65%（§15）、两口径平台交集（§15.3） |
| **`--train-n`** | **32** | 1→32 涨 11.1 点，32→128 饱和（§14），且耗时是 128 的 1/4 |
| **`--thr`** | **4** | 谷底 3~6 的中点；8 会假阳性（§13） |

### 一条重要的补充：256 vs 288

| | 256 | 288 |
|---|---|---|
| 峰值（轻训练） | **21.49%** | 17.64% |
| 峰值（重训练） | **31.65%** | 24.25% |
| 重复性 | 差 3.70 | **差 0.46** |

**256 在两个口径下都更高；288 更稳但更低。**

> **报告口径建议**：主参数写 **256**；若强调"可复现性优先"，可注明"288 的重复性更好（±0.46 vs ±3.70），但命中率低 15~25%"。

## 18. 两条被证伪的假说

| 假说 | 预测 | 实测 | 判定 |
|---|---|---|---|
| "最优链长是 4×64 的折叠谐波" | 320（=5×64）应出现第二峰 | 320 = 13.88%，单调下降，**无第二峰** | ❌ 否定 |
| "碰撞 = PHR 历史足迹匹配数" | 尾部匹配 1→64 应大幅上升 | 20.87 → 18.34，**无单调趋势** | ❌ 否定 |

**为什么链长存在最优区，机制仍未查清**——这是本工作的主要遗留问题。

## 19. 与物理深度的关系

| 量 | 数值 | 定义 | 来源 |
|---|---|---|---|
| PHR 物理深度 | **≈64** | 硬件能存多少条分支足迹 | Linux 内核 `spectre_bhb_k32` + USENIX Sec'25 的 k×2 规则 |
| `HISTORY_SIZE` | **256** | 灌进去多少条链 | 本文实测 |
| 清除循环次数 K | 32 | 内核冲 BHB 要跑几遍 | Arm 白皮书 / 内核 |

交叉推导：

```
Linux 内核：N2 的清除循环 = 32 次（与 A78AE 同组）
USENIX'25 ：A78AE 的 32 次循环 → PHR = 64 条分支（规则：循环次数 × 2）
                          ↓
                N2 的 PHR ≈ 32 × 2 = 64 条分支
```

**三者不可互换。** 灌 256 条进只能记 64 条的寄存器，早先的会被挤出去——这正是"为什么 256 反而最好"仍未查清的原因。
