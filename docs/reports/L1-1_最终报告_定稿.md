# 一、结论

> **在倚天 710 上复现了 BHB 碰撞。关键在于：上游默认的 `HISTORY_SIZE=64` 是给 Cortex-X1 的，
> 在 N2 上必须调到 256。**

> 调整后，训练到攻击目标的命中率为 **17.99%**，训练到安全目标仅 **0.064%**——

# 三、阶段一：L1D Flush+Reload 探针

## 方法与数据

同一 4 KB 对齐地址，各测 200 次、重复 5 轮：

| | min | median | max |
|---|---|---|---|
| hot（命中） | 1 | **1** | 2 |
| cold（未命中） | 7 | **7** | 14 |

- **tick 3/4/5/6 无任何样本**（真空洞）
- 分离比 7.2 ± 0.4（n=5），阈值取 **4**
- 计时源 `cntvct_el0`，**1 tick = 20 ns**

![图 1　探针自检：命中 1 tick、未命中 7 tick，tick 3~6 无任何样本，分离比 7.00×，阈值取 4](img/fig_probe.png)

## 两个附带结论

1. **`dc civac` 在 EL0 可执行**（原预期 SIGILL）→ 本组所有侧信道实验都能做真 Flush+Reload
2. **计数器仅 50 MHz** → 命中被量化为 1 tick，只能定性，不能纳秒级定量

# 四、阶段二：方法与移植

## 4.1 原理（一句话）

> 攻击者用 JIT 在**自选地址**上生成分支链 → 等于**往 BHB 写可控历史** →
> 受害者的间接跳转用被污染的历史预测 → **跳错到攻击者指定的目标** →
> 投机执行 gadget 触碰 `fr_buf` → **用探针看得到**。

**为什么 v2 的硬件缓解挡不住**：v2 给 **BTB 条目打特权标签**；
BHI 污染的是**历史**，受害者命中的是**它自己那条合法条目**，标签机制无从判断（"推测目标复用"）。

## 4.2 三层移植（N2 适配）

| 层 | 原配置 | 改成 | 不改的后果 |
|---|---|---|---|
| **编译** | `$(CC_ANDROID)`（Android NDK） | `gcc`（原生 aarch64） | 报错 `-c: not found` |
| **计时** | `mrs pmccntr_el0` | `isb; mrs cntvct_el0`（50 MHz） | **SIGILL，退出码 132** |
| **参数** | `THR = 100` | `THR = 4` | 每轮 `hits:100`，假阳性 |

**THR=4 是阶段一量出来的**（hot=1、cold=7，3~6 无样本）。
**这就是两个阶段的连接点：先量尺子的刻度，才能给出阈值。**

## 4.3 为什么要重写测量仪

上游 `bhb_brute_force` 有三个设计缺陷：

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | **一次运行只抽 1 条训练链** | 整个 run 只回答"这一条链能否撞上"，运行间方差极大 |
| 2 | **没有零假设分布** | 看到 `hits=51` 不知道"噪声能到多少" |
| 3 | **没有配对对照** | 只能比较不同时间的两次运行 |

**新仪器 `calib.c`**（`snippet.S` 与 JIT 逻辑未改，只重写外层）：

```
对每条随机触发链：
  ① 掷硬币决定 CTRL/MAIN 顺序（消除顺序效应，并记录）
  ② CTRL：训练到安全目标 ftable[0] → 冲刷 → 触发 → 测 load_time
  ③ MAIN：训练到攻击目标 ftable[1] → 冲刷 → 触发 → 测 load_time
  各测 100 次；共 200 条训练链 × 1000 条触发链
```

**四个旋钮**：`--history N`（历史长度）、`--in-place 0|1`、`--iters K`、`--thr T`

## 4.4 首版结论为何是 fail（弯路记录）

为保持过程完整，简要记录首版情况：

| 项目 | 内容 |
|---|---|
| 做法 | 直跑上游 `main.c`，`HISTORY_SIZE` 用默认 64 |
| 数据 | 一次 20 分钟得 42 次过线；另两次分别为 3 次 / 0 次 |
| 复跑检验 | MAIN 0.1% ≈ CTRL 0%（POS 100% 排除测量问题） |
| **当时判定** | **`fail / E004`（信号不可区分）** |

判 fail 的直接理由：**同配置跨运行不可重复**，且受控复跑显示"训练到攻击目标"与"训练到安全目标"没有差别。

**后来查明两个原因**：

1. `HISTORY_SIZE=64` 对 N2 严重不匹配（该长度下命中率仅 0.58%），本就接近测量底噪；
2. 上游实现**每次运行只在开头抽一条训练链**，运行间方差极大，同一配置可以给出 42 / 3 / 0 三种结果。

这两点直接促成了 `calib.c` 的重写，也才有了第五节的结论。
**首版的价值在于暴露了上游实现的问题，而不是它给出的那个数字。**

# 五、结果

## 5.1 主结果（H=256，原地）

| 模式 | 命中率 | 最大 hits | `≥10` 轮数 | `≥51` 轮数 |
|---|---|---|---|---|
| **MAIN（训练到攻击目标）** | **17.99% ± 9.07** | 59 | **160,021（80.0%）** | 38 |
| **CTRL（训练到安全目标）** | **0.064% ± 0.26** | 3 | **0** | 0 |

**20 万轮 CTRL 从未出现一次 `hits ≥ 10`，而 MAIN 有 80% 的轮次超过 10 —— 两个分布完全不相交。**

![图 2　主结果（H=256，原地，20 万轮）：MAIN 均值 17.987、最大 59；CTRL 均值 0.0635、最大 3](img/fig_main.png)

## 5.2 三条对照

| 对照 | 只改这一个变量 | 结果 | 排除了什么 |
|---|---|---|---|
| **CTRL vs MAIN** | 训练到哪个槽位 | 0.064% vs 17.99%（**283×**） | 与训练无关的测量偏差 |
| **异地 vs 原地（H=256）** | 最后一条地址是否复用 | **0 / 600 万次** vs 17.99% | 链长效应、假象 |
| **异地（H=64）** | 同上 | **0 / 4000 万次** | 同上，量级更大 |

![图 3　决定性对照（H=256，各 600 万次测量）：异地命中 0.0000（最大 0），原地 20.7229（最大 57）](img/fig_inplace.png)

## 5.3 HISTORY_SIZE 扫描（单峰，这是本次最关键的发现）

| H | MAIN 命中率 | 最大 | `≥10` 轮数 | CTRL `≥10` |
|---|---|---|---|---|
| 32 | 0.19% | 14 | 1 / 30,000 | 0 |
| 48 | 0.38% | 46 | 15 / 30,000 | 0 |
| 64（**上游默认**） | 0.58% | 43 | 59 / 30,000 | 0 |
| 96 | 1.45% | 75 | 918 / 30,000 | 0 |
| 128 | 3.76% | 68 | 4,876 / 30,000 | 0 |
| 160 | 6.15% | 53 | 6,787 / 30,000 | 0 |
| 192 | 7.36% | 38 | 9,272 / 30,000 | 0 |
| **256** | **20.72%** | 57 | 22,307 / 30,000 | **0** |
| 384 | 0.77% | 29 | 21 / 30,000 | 0 |
| 512 | 0.004% | 46 | 3 / 30,000 | 0 |

**峰值在 256：384 骤降 27 倍，512 再降 190 倍。**

> **解释**：链长小于 BHB 有效长度 → 索引窗口填不满，哈希对不上；
> 链长远超 → 共享的那条地址被挤出有效索引。
> **推断 N2 的 BHB 有效长度量级 ≈ 256 项。**

![图 4　HISTORY_SIZE 扫描（32~256）：MAIN 从 0.19 单调升至 20.72，CTRL 各档 `≥10` 恒为 0](img/fig_sweep.png)

## 5.4 顺序效应（设计校验，H=64 数据）

```
MAIN_MA 0.7436   （MAIN 先跑）      CTRL_AM 0.0520
MAIN_AM 0.5983   （CTRL 先跑）      CTRL_MA 0.0080
```

存在轻微"顺延污染"（先跑者给后跑者留底子）。
**最干净的估计是 `MAIN_MA 0.7436` vs `CTRL_MA 0.0080`（93×）**；
主结果用两种顺序的混合均值，属**保守估计**。

| 之前观测 | 现在的解释 |

# 十、逐字口播稿（9 分钟）

> **（P1）** 老师好，我汇报 L1-1 实验。先说结论：**在倚天710 上成功复现了 BHB 碰撞**，
> 但关键是要改一个参数——上游默认的历史长度 64，在 N2 上必须调到 256。
> 调完之后，命中率从 0.6% 提升到 18%。

> **（P2）** 任务分两步：先建缓存侧信道探针，因为 BHB 的推测执行看不见，只能靠缓存状态反推；
> 再用 vusec 的代码复现碰撞并按 N2 调参。

> **（P3）** 探针是一个校准实验。命中 1 个 tick、未命中 7 个 tick，**3 到 6 这四个刻度一个样本都没有**，阈值定在 4。
> 这台机器计数器 50 兆，1 tick 是 20 纳秒。
> 有个意外发现：**arm64 上替代 clflush 的 `dc civac`，在用户态可以执行**，这对组里其他同学也有用。

> **（P4）** 原理一句话：攻击者在自选地址上摆一串分支，等于往 BHB 里写一段可控历史；
> 受害者用被污染的历史预测，就会跳错。v2 的硬件缓解是给 BTB 打标签，
> 而 BHI 污染的是历史，受害者命中的是它自己那条合法条目，所以挡不住。

> **（P5）** 移植做了三处：原生 gcc 替代 Android 交叉编译；PMU 计数器换成虚拟计数器，因为这台机器读 PMU 会直接崩；
> 阈值从 100 改成 4，因为计时单位从 CPU 周期变成 20 纳秒的 tick。
> **这个 4 是实验一量出来的。**

> **（P6）** 但直接跑上游代码，结果自相矛盾：同配置一次出现 42 次，另一次 0 次。
> 排查后发现上游程序有个设计缺陷：**每次运行只抽一条训练链**，整个 run 只回答"这一条链行不行"。
> 所以我重写了外层测量逻辑：**每条触发链都做配对对照**——同一条链，先训练到攻击目标测一遍，再训练到安全目标测一遍。

> **（P7）** 结果是：训练到攻击目标，命中率 **17.99%**；训练到安全目标，**0.064%**。
> **差 283 倍**。而且 20 万轮里，对照组一次都没出现过强命中，实验组有 80% 的轮次超过 10 次命中。
> 再做一个对照：把"最后一条地址复用"这个条件关掉，600 万次测量，**一次都没有**。

> **（P8）** 最关键的是这个：我扫了历史长度从 32 到 512。
> 32 是 0.19%，64 是 0.58%，128 是 3.76%，**256 是 20.72%**，384 掉到 0.77%，512 几乎归零。
> **单峰，峰值在 256。**
> 这说明上游给的 64 是给 Cortex-X1 的，在 N2 上严重不匹配。
> **这就是"哪些参数要按 N2 调"的答案。**

> **（P9）** 限制有五个：256 是扫描峰值不是精确值；没做跨特权；没做跨租户；顺序效应约 20%；主结果只跑了一次。
> 下一步想细扫 192 到 320 定位峰值，然后用最优长度重跑上游程序验证。谢谢。

# 十一、问答预案

| 问题 | 回答 |
|---|---|
| **怎么证明这不是测量假象？** | 三条独立对照：训练目标（283×）、原地/异地（4600 万次全 0）、长度剂量-反应（单峰） |
| **为什么认定 256 是 BHB 长度？** | 只是"有效长度量级"——扫描单峰、384 后崩塌。精确项数需要细扫，目前精度 ±32 |
| **为什么上游用 64？** | 那是给 Cortex-X1 的默认值，仓库里没有 N2 的条目，`CUSTOM_UARCH` 全是 TODO |
| **为什么 THR=4，WFY 用 6？** | 计时口径不同：他保留 `fence()`（`dsb ish`），我移除。屏障抬高读数，阈值随之抬高。各自用 ruler 校准，不可跨口径比较 |
| **为什么用 cntvct？** | `perf_event_paranoid=4`、`PMUSERENR_EL0.EN=0`，读 `pmccntr` 直接 SIGILL |
| **之前判 fail 是怎么回事？** | 那是用上游默认 64 跑的；重做后证明是参数不匹配，不是没有漏洞 |
| **这个能用来攻击吗？** | 这是**原语**，只证明"能骗 CPU 跳错"，没做数据泄漏和跨特权。要成攻击还需自定义内核与地址信息 |
| **17.99% 稳定吗？** | 主结果只有一次 20 万轮运行；扫描中 256 出现两次（16.6 / 20.7），一致性尚可，仍需复跑确认 |
